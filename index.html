pi-magpie-bot

查看源码 ↗
解决什么问题
把对话、记忆与提醒放到自己的设备上，通过 Android、网页或 Telegram 使用同一个助理。
我的实现与上游
实现渠道适配、记忆与提醒、工具审批和 Android 界面。属于基于上游组件的应用集成与二次开发：持久化运行依赖 earendil-works/pi，模型网关使用 yetone/magpie，并非自行重写这些引擎。第三方组件说明明确未打包第三方源码。
如何跑起来
按仓库手动安装说明，先安装 Node.js 24+ 与 pnpm，再执行：
git clone https://github.com/mazihua-lgtm/pi-magpie-bot.git
cd pi-magpie-bot
pnpm install
pnpm start
# 浏览器打开 http://127.0.0.1:8787
已验证到哪里
仓库提供架构文档、安装说明与测试入口。c12c278 的 CI 通过；随后 cac407d 的 CI 失败，停在依赖安装步骤。当前不能概括为“CI 全绿”。
已知局限
首次启动会下载网关等依赖，需要网络；免费模型渠道有额度与可用性限制，对话会发送至所选模型服务。企业微信尚未用真实机器人验证；手机读屏与点按控制尚未实现。此页没有重新执行端到端设备测试。

问律 wenlv

查看源码 ↗
解决什么问题
法律咨询中先查清要件事实，再核对法条依据；事实有缺口或引用核不实，就阻止直接输出结论。
我的实现与上游
实现 YAML 案由规则、追问状态机、法条核验与模板报告。仓库未声明基于某个上游应用二次开发；依赖 Python / PyYAML，核验数据来自国家法律法规数据库。这里的核心是规则与流程，不是让模型自由生成法律判断。
如何跑起来
需要 Python 3.10+，建议在独立虚拟环境安装：
pip install git+https://github.com/mazihua-lgtm/wenlv
wenlv --describe "朋友借钱不还，有借条"
已验证到哪里
0db5de4 的测试通过，工作流覆盖 Python 3.10–3.13 的离线单元测试及案由加载检查。核验用例使用假数据源，不证明官方库此刻可访问。
已知局限
仅覆盖仓库列出的请求权基础；案由匹配基于关键词，不核实证据真伪，不提供全量判例检索。在线核验依赖官方库，失败时不出结论。技术工具不能替代执业律师，不构成法律意见。

垂直案例 / 事实核验流程

a-share-factcheck

查看源码 ↗
解决什么问题
从 A 股财报描述里抽取股票代码、报告期、指标、金额与增速，逐条对照指定来源；没有依据就返回无法核实。
我的实现与上游
实现规则抽取、金额与增速比对、来源标记及 CLI / MCP 接口。核查规则由本项目实现，基于 AKShare、FastMCP、Pydantic 等组件集成；不是把第三方行情摘要当作原始公告，也未声称从零实现这些组件。
如何跑起来
在 Python 虚拟环境中，从仓库安装后运行附带的公告快照示例：
git clone https://github.com/mazihua-lgtm/a-share-factcheck.git
cd a-share-factcheck
pip install -e '.[dev]'
finchecker --file examples/2025-disclosures.txt
已验证到哪里
26754d8 的 CI 通过。仓库 README 列出公告标题、链接、页码与报告期，可回溯快照依据；此页未逐项重新审计公告。
已知局限
默认是人工摘录的有限公告快照，不自动更新。规则未抽取到的语句不在核查范围内；通过仅代表已抽取断言与选定来源在容差内一致。演示使用的虚构数据与真实来源分开标记。仅供人工研究，不提供交易功能或投资建议。
